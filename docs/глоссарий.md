# Глоссарий: как называть вещи в docapp

Документ для людей. Один термин — одно значение. Если в коде, ТЗ или разговоре
слово употреблено иначе — это ошибка, и её надо исправить, а не «понять по контексту».

## Термины

| Термин | Значение | Пример в docapp |
|---|---|---|
| **Модуль** | Всё, у чего есть интерфейс и реализация: функция, класс, пакет. Масштаб не важен. | пакеты `core`, `people`, `records`, `ai`, `wiki`, `needs`, `duty`, `summary`; `AnesthesiaService` — тоже модуль, поменьше |
| **Интерфейс** | Всё, что нужно знать вызывающему: подписи, порядок вызовов, ошибки, ограничения. Не только типы. | `AnesthesiaService.create/list_mine/update/delete` + правило «править можно только своё» |
| **Реализация** | Код внутри модуля. | тело `NeedsService`, SQL в `needs/store.py` |
| **Шов** | Место, где живёт интерфейс модуля и где поведение можно подменить. | `AnesthesiaService` — шов между HTTP и хранилищем |
| **Адаптер** | Конкретная вещь на шве: слот, который кто-то занимает. | `SqliteNeedsStore` — адаптер хранилища; роутер — **HTTP-адаптер** |
| **Глубина** | Сколько поведения за единицу интерфейса. Глубокий модуль — маленький интерфейс, много внутри. | `Catalog`: 8 методов снаружи, внутри YAML, mtime-перечитывание, валидация |
| **Рычаг** | Что выигрывают вызывающие от глубины. | один механизм БД вместо четырёх копий — рычаг 4 |
| **Локальность** | Что выигрывают сопровождающие: изменение и проверка в одном месте. | миграции схемы в `core/db.py` — правишь один файл, а не четыре |

## Слова, которых не используем

- **Компонент**, **сервис**, **API**, **граница (bounded context)** — вместо них
  «модуль», «интерфейс», «шов».
- Особенно **«сервис»**: у нас есть классы `NeedsService`, `DutyService` — это
  реализация внутри модуля, а не отдельный архитектурный вид. Называть их
  «сервисным слоем» как роль в архитектуре нельзя.
- **«Подприложение»** — вычеркнуто (см. ниже). В коде — «модуль», в интерфейсе для
  людей — «раздел».

Слово осталось только в трёх местах, и это нарочно: в этой статье, в ADR-0022 и в
таблице решений `docs/ТЗ-каркас.md` — везде речь о самом слове, а не о вещи. В
описаниях кода, тестов, README и остальных документов его нет (проверяется
`grep -ri подприложен`).

## Почему «подприложение» вычеркнуто

Слово вводило в заблуждение: под ним понимали то роутер, то пакет, то раздел меню,
то отдельную БД. Роутер — это **не** архитектурная единица, а адаптер. Он:

- не владеет данными;
- не хранит правила (сейчас хранит: сборка отчёта в `needs/router.py`, группировка
  выгрузки в `duty/router.py` — это чинится, см. ADR-0017);
- не имеет своего жизненного цикла;
- делает одно: переводит HTTP-запрос в вызов интерфейса модуля.

Поэтому «модуль» и «роутер» — из разных категорий. Модуль владеет; роутер переводит.
У модуля может быть два роутера (страница + JSON-API), а может быть ноль —
`core.db` наружу по HTTP не вызывается вовсе.

## Два правила, из которых следует всё остальное

1. **Правило владения.** У каждых данных ровно один модуль-владелец, и правила про
   эти данные живут только там.
   Анестезии принадлежат `records`. Сотрудники — `people`. Заявки и каталог —
   `needs`. Отчёты о дежурствах — `duty`. Источники и статьи — `wiki`.

2. **Правило шва.** Пересечь шов можно только через интерфейс. Если модулю нужны
   данные соседа — он вызывает интерфейс соседа, а не читает его таблицу.
   Нарушение сегодня: `needs/router.py`, `duty/router.py`, `wiki/router.py` читают
   `app.state.employees` напрямую, потому что модуля-владельца сотрудников как
   интерфейса не существовало.

## Как это звучит правильно

> Модуль **`needs`** владеет заявками и закрытиями недель. Его интерфейс —
> `NeedsService`. Роутер `/needs` — HTTP-адаптер этого модуля. Таблицы `needs_*`
> принадлежат только `needs`; модуль `duty` их не читает и не пишет.

> Модуль **`records`** владеет анестезиями. Раздел «Анестезии» и планируемый раздел
> «Сводка по анестезиям» — два разных модуля над одними данными: второй обращается к
> анестезиям только через интерфейс первого (`records`), а не читая таблицу `anesthesia`.

> Модуль **`wiki`** владеет источниками и статьями. Роутер `/compendium` — его
> HTTP-адаптер. Раздел в меню называется «Компендиум», модуль в коде — `wiki`:
> разные роли одного и того же, и это нормально, пока названо осознанно.
