# ТЗ v2.3 (адаптация под docapp): Консультант по приказам — подприложение «Приказы»

> **Статус: СОГЛАСОВАНО.** LLM — RouterAI (https://routerai.ru/api/v1). Эмбеддинги — **вариант A1** (всё через RouterAI `/embeddings`, один ключ). История диалога — есть. Учёт токенов — есть. Загрузка приказов — только заведующий, офлайн-сборка индекса + загрузка файла.
> **For Hermes:** реализация субагентами (subagent-driven-development), по одной задаче с двухэтапной проверкой и коммитом.

**Цель:** заменить заглушку `/orders` (ADR-9) реальным подприложением «Приказы» — ИИ-консультантом по внутренним приказам отделения анестезиологии. LLM и эмбеддинги — через **RouterAI** (OpenAI-совместимый, оплата в рублях, один API-ключ). Новый код полностью изолирован от существующего.

**Главный принцип:** не сломать работающее. Существующие 125 тестов остаются зелёными; существующие файлы меняются по минимуму (§2).

## 3. Архитектура и рабочий процесс

**✅ Вариант A1 (ВЫБРАН): всё через RouterAI, один ключ**
- **Индексация** — на рабочей станции заведующего: CLI `python -m docapp.consult.build` читает приказы из папки, нарезает на фрагменты, вызывает RouterAI `/embeddings` батчами (100–500 текстов/запрос), собирает переносимый файл индекса `consult.db` (документы + чанки + эмбеддинги).
- **Сервер** — загружает готовый `consult.db` в `data/consult/`, «перезагрузить индекс» (head). При вопросе: RouterAI `/embeddings` (1 вызов, вектор вопроса) + `/chat/completions` (стриминг ответа). Сервер — чистый HTTP + numpy, ноль ML-зависимостей.
- Совместимость векторов гарантирована (обе стороны — одна модель провайдера). Затраты копеечные.

## 4. Хранилище (`data/consult/consult.db`, переносится между машинами)

```sql
CREATE TABLE documents (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    filename    TEXT NOT NULL,
    doc_number  TEXT NOT NULL DEFAULT '',
    title       TEXT NOT NULL DEFAULT '',
    added_at    TEXT NOT NULL,
    full_text   TEXT NOT NULL DEFAULT '',   -- полный текст (чтение «Приказа» целиком)
    source      BLOB,                        -- оригинальный файл (.docx/.pdf)
    source_name TEXT NOT NULL DEFAULT ''     -- имя файла для скачивания
);
CREATE TABLE chunks (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id INTEGER NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index INTEGER NOT NULL,
    section     TEXT NOT NULL DEFAULT '',
    text        TEXT NOT NULL,
    embedding   BLOB NOT NULL               -- float32 numpy
);
CREATE TABLE messages (                      -- история диалогов + учёт токенов
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    employee_id     INTEGER NOT NULL,
    conversation_id TEXT NOT NULL,           -- UUID, генерится на клиенте
    role            TEXT NOT NULL,           -- 'user' | 'assistant'
    content         TEXT NOT NULL,
    citations       TEXT NOT NULL DEFAULT '[]',   -- JSON
    prompt_tokens   INTEGER NOT NULL DEFAULT 0,   -- токены входа (usage из финального чанка LLM)
    completion_tokens INTEGER NOT NULL DEFAULT 0, -- токены выхода
    created_at      TEXT NOT NULL
);
CREATE INDEX idx_chunks_doc ON chunks(document_id);
CREATE INDEX idx_msg_conv ON messages(conversation_id, created_at);
CREATE INDEX idx_msg_emp  ON messages(employee_id, created_at);
```
Поиск: при старте/перезагрузке чанки (~10–20 тыс.) загружаются в память (numpy) — cosine за миллисекунды + BM25 (rank-bm25) → RRF → топ-5.

Конфиг — env `CONSULT_*` (в духе `docapp.config`): `CONSULT_API_KEY`, `CONSULT_BASE_URL=https://routerai.ru/api/v1`, `CONSULT_LLM_MODEL`, `CONSULT_EMBED_MODEL`, `CONSULT_INDEX_DIR` (по умолчанию `data/consult/`). Ключ — только env, `.env` уже в .gitignore.

## 5. Функциональные требования

- F1. `/orders` — консультант: поле вопроса, стриминг ответа, цитаты «Приказ №X · раздел Y» (раскрываются, показывают фрагмент). Все роли.
- F2. Строгий граундинг: ответ только по фрагментам; нет в корпусе → «В предоставленных приказах эта информация не найдена».
- F3. История диалога: сообщения в БД, в контекст LLM уходят последние ~6 реплик беседы; при открытии страницы показывается прошлая беседа; кнопка «Новый разговор».
- F4. Аналитика для заведующего — страница «Вопросы»: что спрашивают (по сотрудникам и датам, с цитатами) и **расход токенов** (сумма prompt+completion по сотруднику, по дням, всего). Только `head`.
- F5. **Учёт токенов:** LLM-клиент собирает `usage` из финального чанка стрима (OpenAI-формат: `prompt_tokens`, `completion_tokens`); сохраняется в `messages` при каждом ответе. Если usage отсутствует — записываются нули (не падает).
- F6. `GET /orders/documents` — список документов + дата сборки индекса (всем ролям).
- F7. `POST /orders/reindex` — пересборка индекса из статичной папки приказов в фоне (статус — `GET /orders/status`, повторный запуск до завершения — 409). Только `head`. Веб-загрузка файлов — F11.
- F8. PWA с телефона (адаптивная, без CDN).
- F9. **Статичная папка приказов**: `CONSULT_DOCS_DIR` (по умолчанию `data/consult/documents/`); CLI без аргумента индексирует её; обновление — положить файлы в папку и запустить команду заново (пересборка полная).
- F10. **Чтение и скачивание приказов** (всем ролям): в списке документов ссылки «Читать» и «Скачать»; `GET /orders/documents/{id}` — страница полного текста; `GET /orders/documents/{id}/download` — оригинальный файл (из `source` в БД; если оригинала нет — .txt из `full_text`).
- F11. **Веб-загрузка документов с авто-переиндексацией** (только заведующий): `POST /orders/documents/upload` (.docx/.pdf, повторный запуск до завершения — 409); файлы сохраняются в статичную папку приказов, сервер сам пересобирает индекс (эмбеддинги через RouterAI); `GET /orders/status` — статус пересборки (busy/started_at/finished_at/error + documents/chunks). **История диалогов сохраняется при пересборке индекса** — сообщения `messages` мигрируют из старого файла в новый (пересборка идёт во временный файл с атомарной заменой).
- N1. Ответ ≤ 15 с. N2. Переиндексация ≤ 10 мин. N3. Все тесты зелёные. N4. Сервер без тяжёлых зависимостей.

## 6. План задач для субагентов

- **T1.** Пакет `consult/` + `config.py` (env) + `store.py` (схема: documents, chunks, messages с токенами) + тесты.
- **T2.** Парсеры `parsing.py` (.docx/.pdf → Block) + фикстуры + тесты.
- **T3.** Нарезка `chunking.py` (структурная ~600 симв., метаданные: номер приказа регэкспом, раздел/пункт) + тесты.
- **T4.** `embed.py`: клиент RouterAI `/embeddings` (батчи, retry) + фейк-провайдер в тестах.
- **T5.** `build.py` — CLI сборки индекса: папка приказов → `consult.db`. Тесты на маленьком корпусе.
- **T6.** `search.py`: cosine (numpy) + BM25 + RRF + тесты.
- **T7.** `llm.py`: стриминговый OpenAI-совместимый клиент (httpx), **сбор `usage` из финального чанка**; MockTransport-тесты (включая отсутствие usage).
- **T8.** `service.py`: загрузка индекса, `ask()` (история из БД + события delta/done+citations + **сохранение токенов**), журнал; граундинг-промпт; тесты с фейками.
- **T9.** `router.py` + правка `app.py` (замена заглушки) + правка 2 тестов `test_web.py` + API-тесты (роли: вопрос всем, reindex/аналитика только head).
- **T10.** `consult.html` + `consult.js` + `consult.css`: чат со стримингом, цитаты, история («Новый разговор»), вкладки «Документы» и «Вопросы» (head: список вопросов + расход токенов).
- **T11.** Сквозная проверка: полный pytest, ручной прогон с реальным ключом, замер времени, документация (ADR-10 в README + ТЗ в `docs/` — уже сделано).
- **T12.** Слой данных: `config.docs_dir` (CONSULT_DOCS_DIR), схема documents + `full_text`/`source`/`source_name`, `build_index` без аргумента папки (статичная папка, сохранение полного текста и оригинала), CLI без аргумента.
- **T13.** Чтение/скачивание: `GET /orders/documents/{id}` (страница полного текста, шаблон document.html), `GET /orders/documents/{id}/download` (оригинал или .txt), id в `documents()`, тесты.
- **T14.** UI: вкладка «Документы» всем ролям, ссылки «Читать»/«Скачать», README (статичная папка + скачивание), E2E-расширение.
- **T15.** Веб-загрузка документов (F11): `POST /orders/documents/upload` (только head, .docx/.pdf, busy → 409), фоновая пересборка `_run_rebuild` во временный файл + атомарная замена, **миграция `messages` при пересборке** (история и токены не теряются), `GET /orders/status`, форма загрузки в UI, E2E-тесты (загрузка → пересборка → доступность; история на месте после reindex).

## 7. Открытые вопросы (не блокируют)

1. **Модель LLM на RouterAI** — `CONSULT_LLM_MODEL` в .env (дефолт `gpt-4o-mini`; заведующий подставит свою при первом запуске).
2. **Embedding-модель RouterAI** — `CONSULT_EMBED_MODEL` (дефолт `text-embedding-3-small`); размерность фиксируется в индексе и проверяется при загрузке.
3. OCR для сканов — фаза 2, не блокирует.
