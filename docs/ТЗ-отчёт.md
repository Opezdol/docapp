# ТЗ: «Отчёт» (начисления) — подприложение заведующего

## Цель

Заведующий учитывает ведомость начислений (xlsx из бухгалтерии): сопоставляет
строки ведомости с записями анестезий, помечает записи как «начислено» и
формирует месячные итоги по врачам и медсёстрам. Врач и медсестра видят свой
итог за месяц и какие их записи учтены.

Одновременно меняется UI заведующего: главная страница разносится по вкладкам
«Анестезии» (форма врача) и «Отчёт» (данное подприложение).

## Зафиксированные решения

- **Деньги отдельно от записей**: суммы начислений живут в отдельной таблице
  `accrual` (итог за месяц на сотрудника), а записи анестезий получают только
  флаг «начислено» (`accrued_at`). На записи суммы **не** хранятся.
- **Точность**: суммы — `decimal.Decimal` (в SQLite — TEXT, десятичная строка;
  в Python — точная арифметика без погрешности `float`).
- **Ведомость всегда полная за месяц** → переимпорт пересчитывает месяц
  целиком (сброс начислений и флагов месяца → применение новой ведомости).
- **Месяц** выбирает заведующий в UI перед загрузкой ведомости.
- **Сопоставление** — по нормализованной фамилии (первое слово полного ФИО,
  регистр/пробелы нормализуются); однозначные сопоставляются автоматически,
  неоднозначные и ненайденные показываются для ручной проверки **до** применения.
- **Рестайл формы анестезий** в стиле формы «расходки» — только интерфейс
  заведующего (вкладка «Анестезии»); врачи не затрагиваются.

## Роли и доступ

- **Заведующий (`head`)** — всё подприложение «Отчёт»: выбор месяца, загрузка
  ведомости, просмотр начислений, применение.
- **Врач (`doctor`)** — только своя сумма за месяц и свои записи с пометкой
  «начислено» (раздел «Мои записи»).
- **Медсестра (`nurse`)** — только своя сумма за месяц и записи со своим
  участием с пометкой «начислено» (раздел «Анестезии с участием»).
- **`editor`, `head_nurse`** — без доступа к «Отчёту» (не цель текущего ТЗ).

## Модель данных

Основная БД `docapp.db` (не отдельная, как у needs/duty/wiki — данные об
анестезиях уже там).

### Миграция v3: флаг «начислено» на записи

```sql
ALTER TABLE anesthesia ADD COLUMN accrued_at TEXT;  -- ISO, NULL = не начислено
```

### Новая таблица `accrual` (итоги начислений за месяц)

| колонка | тип | примечание |
|---|---|---|
| `employee_id` | INTEGER | REFERENCES employees(id) |
| `month` | TEXT | `YYYY-MM` |
| `amount` | TEXT | десятичная строка, суммарно за месяц (Decimal) |

`PRIMARY KEY (employee_id, month)` — один итог на сотрудника за месяц.

Сумма «врачу» из ведомости зачисляется на `doctor_id` записи, сумма «сестре» —
на `nurse_id`. Месяц начисления — месяц `date` записи (дата подачи; это наша
оценка рабочего месяца, т.к. даты процедуры в системе нет — ADR-14).

## Формат xlsx (требует подтверждения по реальной выгрузке)

- Первый лист.
- Шапка опциональна (определяется эвристикой, фиксируется после пробы на
  реальном файле).
- Столбцы по порядку: **Фамилия пациента | Сумма врачу | Сумма сестре**.
- Суммы — числа (рубли, дробная часть допускается); пустая сумма = 0.

## Требования

### T1. Вкладки заведующего
Главная страница заведующего — вкладки «Анестезии» и «Отчёт»; по умолчанию
«Анестезии». «Анестезии» — текущая форма врача (свои записи + добавление).
Критерий: у заведующего обе вкладки, переключение работает; врачи видят
страницу как раньше.

### T2. Рестайл формы анестезий (только заведующий)
Форма «Новая анестезия» у заведующего оформлена в стиле формы «расходки»
(карточки/вкладки, палитра `#1565c0`, переиспользование классов `needs-*`).
Поведение формы не меняется.
Критерий: визуальное соответствие; добавление/правка/удаление записи работает.

### T3. Схема
Миграция v3 (`anesthesia.accrued_at`) и таблица `accrual` создаются
автоматически; `SCHEMA_VERSION` основной БД → 3, миграция добавлена в
`_MIGRATIONS` без правки опубликованных.

### T4. Выбор месяца
В «Отчёте» заведующий выбирает месяц (input `type="month"`). По нему грузятся
начисления и ведомость применяется к этому месяцу.

### T5. Загрузка и парсинг ведомости
Загрузка `.xlsx`, парсинг через `openpyxl`. Строки без фамилии или с нечисловой
суммой — ошибка с указанием строки.
Критерий: корректный файл разбирается; битый файл даёт понятную ошибку.

### T6. Сопоставление (предпросмотр до применения)
Для каждой строки ведомости ищутся записи анестезий выбранного месяца по
нормализованной фамилии. Результат — предпросмотр: «сопоставлено» (однозначно),
«не найдено», «неоднозначно» (несколько записей с одной фамилией). Ничего в БД
не пишется до явного «Применить».
Критерий: предпросмотр показывает три группы; заведующий может вручную указать
запись для неоднозначных/ненайденных (или пропустить).

### T7. Применение (пересчёт месяца целиком)
По команде «Применить» атомарно: (1) у всех записей выбранного месяца снять
`accrued_at`; (2) для сопоставленных — проставить `accrued_at = now`;
(3) пересчитать `accrual` месяца (удалить записи месяца → вставить суммы по
сотрудникам). Повторная загрузка того же месяца даёт тот же результат
(идемпотентность).
Критерий: повторный импорт не дублирует; расхождение ведомости и БД исправляется
переимпортом.

### T8. Просмотр начислений (заведующий)
Таблица по сотрудникам: ФИО, роль, сумма начислений за выбранный месяц.
Дополнительно — список записей месяца с пометкой «начислено».
Критерий: видны итоги за месяц по каждому сотруднику и учтённые записи.

### T9. «Мои записи» (врач)
Врач видит свой итог начислений за месяц и свои записи с пометкой «начислено».
Критерий: сумма видна только своя; чужие суммы не отображаются.

### T10. «Анестезии с участием» (медсестра)
Медсестра видит свой итог начислений за месяц и записи со своим участием с
пометкой «начислено».
Критерий: сумма видна только своя.

### T11. Приватность (152-ФЗ)
API отдаёт суммы только «свои» (врачу/сестре) или все (заведующему). Чужие
суммы не утекают через `/report`-эндпоинты.
Критерий: эндпоинты проверяют роль; тесты покрывают 403/фильтрацию.

## Не-цели (вне этого ТЗ)

- Отдельный этап «оплачено» (сейчас — только «начислено»); при необходимости
  добавляется позже отдельной миграцией.
- Ручная правка сумм/записей начислений заведующим (только переимпорт).
- Доступ `editor`/`head_nurse` к «Отчёту».

## Слабые места (принятые риски)

1. **Сопоставление по фамилии** — неоднозначности/опечатки; смягчается
   предпросмотром и ручной доводкой (T6).
2. **Формат xlsx** — точные колонки/шапка подтверждаются на реальной выгрузке
   до финализации (раздел «Формат xlsx»).
3. **Месяц = дата подачи** — нет даты процедуры (ADR-14); если бухгалтерия
   привязывает начисление к иному месяцу, потребуется уточнение источника.
4. **Дробность сумм** — Decimal хранит точно, но при выводе округление до
   копеек задаётся единообразно.

## План реализации

1. Согласовать ТЗ (этот документ) + ADR-0024 (файлом в `docs/adr/`; номера 16–23
   заняты решениями по каркасу — см. `docs/ТЗ-каркас.md`).
2. Миграция v3 + таблица `accrual` (store).
3. Бэкенд `src/docapp/report/`: store/service/router (список, импорт,
   сопоставление, применение, итоги) + тесты.
4. UI заведующего: вкладки «Анестезии» | «Отчёт» + рестайл формы.
5. Суммы/статус в «Моих записях» врача и «Анестезиях с участием» сестры.
6. Тесты e2e и вычитка.
