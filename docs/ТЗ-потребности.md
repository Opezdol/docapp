# ТЗ v1.0: Потребности — раздел для старшей сестры

> **Статус: РЕАЛИЗОВАНО (T1–T10).** Все открытые вопросы брифинга закрыты.
> **Сверх ТЗ добавлено (2026):** выбор точки пополнения сеткой карточек (как доска
> старшей) вместо выпадающего списка — медсестра кликает по карточке точки и сразу
> попадает в форму заявки этой точки.
> **For Hermes:** реализация субагентами (isolated-subapp-subagents), по одной задаче
> с двухэтапной проверкой и коммитом; полный pytest зелёный после каждой интеграционной задачи.

**Цель:** раздел для сестёр и старшей сестры: еженедельные заявки на расходку
(медикаменты, растворы, расходные материалы) от точек пополнения двух баз
(Ленская, Таймырская) и результирующая потребность для аптеки. Полная изоляция
от существующего кода; основная `docapp.db` не затрагивается.

**Главный принцип:** не сломать работающее. Существующие 224 теста остаются зелёными;
правки существующих файлов — по явному списку (§2).

## Решения по открытым вопросам брифинга (закрыты)

1. **Роль** — новая `head_nurse` (старшая сестра): всё, что у медсестры, плюс
   «Потребности» полностью (доска, правки, закрытие, отчёты, аналитика). Админка
   «Приказов» (`reindex`, «Вопросы») ей недоступна — проверки `== HEAD` отсекают
   автоматически.
2. **Справочник** — файл `data/needs/catalog.yaml`: базы, точки, группы, препараты,
   единицы. Данные, не код, не БД. Авто-перечитывание по mtime.
3. **Поток** — календарные недели (пн–вс), сброс в понедельник; точка = один запрос
   в неделю; статусы `draft` / `sent`; закрытие по базе (два отчёта: Ленская, Таймырская).
4. **Отчёт** — Excel .xlsx (openpyxl), два листа: «Растворы» (препарат × точки + итог)
   и «Потребность» (остальное суммарно по группам).
5. **Импорт** — не нужен в v1: справочник правится файлом.
6. **Связь с «Приказами»** — нет (явный non-goal); задел — группа «Растворы» в файле
   и снимки в строках запросов.

## 3. Архитектура и рабочий процесс

### Рабочий цикл (как согласовано)

1. Неделя = календарная (пн–вс), `week_start` = понедельник. Сброс для сестёр —
   в понедельник: прошлая неделя уходит в историю (БД), форма пустая.
2. Сестра открывает точку пополнения (любую, обе базы), ищет препарат по подстроке
   в каталоге, добавляет в список, проставляет количества, сохраняет черновик
   или отправляет.
3. Свой запрос (draft и sent) правится до закрытия базы. Чужой sent — просмотр.
   Чужой draft — не виден. После закрытия базы — просмотр до конца недели.
4. Одна точка = один запрос в неделю (`UNIQUE(base, point, week_start)`).
5. Старшая видит доску: точки обеих баз × статус (нет запроса / черновик / отправлено)
   + автор. Правит любой запрос (автор остаётся исходный).
6. Закрытие по базе (кнопки «Закрыть Ленскую» / «Закрыть Таймырскую»):
   предупреждение о неотправленных точках (не блокирует), фиксация в `closures`,
   генерация отчёта. Отчёт-форма для аптеки — два отчёта, по базам.
7. Переоткрытие — удаление строки `closures` (без меток истории), правки, повторное
   закрытие → пересборка отчёта.
8. Строки без количества в отчёт не попадают; при отправке — предупреждение.

### Каталог (`catalog.yaml`)

```yaml
bases:
  Ленская: [травма, урология, НХО/СКП, Эндоскопия, ПМУ, Коронары]
  Таймырская: [экстренная, план 2 этаж, гной, малая гинекология, СКП гинекология, микрохирургия]
groups:
  Неспецифика:
    Атропин: амп
    # ...
```

- Чтение при старте + авто-перечитывание по mtime (проверка при каждом обращении, кэш).
- Ошибка парсинга/валидации → последняя рабочая версия + warning в лог.
- Группа **«Растворы» — особая** (в отчёте поточково); не переименовывать
  (определяется по имени группы).
- Строки запросов хранят **снимки**: `item`, `unit`, `grp` — правки файла
  не ломают историю и отчёты за прошлые недели.

### Хранилище (`data/needs/needs.db`)

```sql
CREATE TABLE requests (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    base        TEXT NOT NULL,
    point       TEXT NOT NULL,
    week_start  TEXT NOT NULL,              -- 'YYYY-MM-DD', понедельник недели
    author_id   INTEGER NOT NULL,           -- id сотрудника из основной БД
    status      TEXT NOT NULL DEFAULT 'draft',  -- 'draft' | 'sent'
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL,
    UNIQUE (base, point, week_start)
);
CREATE TABLE request_lines (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    request_id  INTEGER NOT NULL REFERENCES requests(id) ON DELETE CASCADE,
    item        TEXT NOT NULL,              -- снимок названия
    unit        TEXT NOT NULL DEFAULT '',   -- снимок единицы
    grp         TEXT NOT NULL DEFAULT '',   -- снимок группы
    qty         INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE closures (
    base        TEXT NOT NULL,
    week_start  TEXT NOT NULL,
    closed_at   TEXT NOT NULL,
    closed_by   INTEGER NOT NULL,
    PRIMARY KEY (base, week_start)
);
```

Конфиг — env `NEEDS_*`: `NEEDS_DB` (по умолчанию `data/needs/needs.db`),
`NEEDS_CATALOG` (по умолчанию `data/needs/catalog.yaml`). Ключей/секретов нет.

## 4. Функциональные требования

- F1. `GET /needs` — страница раздела. Доступ: nurse, head_nurse, head.
  Doctor — 403.
- F2. Каталог из файла: базы, точки, группы, препараты, единицы; поиск по подстроке
  названия (клиентская фильтрация; каталог ~64 позиции).
- F3. Форма сестры: выбор точки (группировка по базам) → список выбранных позиций +
  поля количеств → «Сохранить» (draft) / «Отправить» (sent). Предупреждение
  «N позиций без количества» при отправке.
- F4. Правила правок: свой запрос (draft/sent) — правка до закрытия базы; чужой
  sent — просмотр; чужой draft — скрыт; закрытая база — просмотр до конца недели;
  понедельник — сброс (история остаётся в БД).
- F5. Одна точка = один запрос в неделю (повторное открытие точки показывает
  существующий запрос).
- F6. Доска старшей: точки × статус (нет/черновик/отправлено) + автор; правка любого
  запроса; закрытие по базе (список неотправивших в предупреждении); переоткрытие.
  Только head_nurse/head.
- F7. Отчёт-форма: генерация при закрытии (.xlsx, два листа: «Растворы» — препарат ×
  точки + ИТОГО; «Потребность» — остальные группы суммарно по препаратам, секции
  по группам, подытог). Шапка: база, неделя (даты пн–вс), дата формирования.
  Просмотр HTML + скачивание .xlsx. Только head_nurse/head.
- F8. Аналитика: фильтры (интервал недель, база, точка, группа; комбинируются),
  учитываются только `sent`-запросы (закрытие не требуется); растворы — поточково,
  остальное — суммарно; таблица на экране + экспорт .xlsx. Только head_nurse/head.
- F9. Автор запроса сохраняется при правке старшей.
- F10. PWA: адаптивная мобильная вёрстка, без CDN, русский язык.
- F11. «Приказы»: nurse → 403 на всех маршрутах консультанта; пункт меню скрыт
  у nurse. (Изменение ADR-10 — фиксируется в README.)
- N1. Страницы открываются ≤ 1 с (без сети). N2. Все тесты зелёные.
  N3. Сервер без тяжёлых зависимостей (pyyaml, openpyxl — лёгкие).

## 5. План задач для субагентов

- **T1.** Пакет `needs/` + `config.py` (env `NEEDS_DB`/`NEEDS_CATALOG`) + `catalog.py`
  (YAML: парсинг, валидация структуры, авто-перечитывание по mtime, поиск по подстроке,
  группа «Растворы» как особая) + тесты (валидный/битый/изменённый файл).
- **T2.** `store.py`: схема (requests, request_lines, closures), CRUD,
  `UNIQUE(base, point, week_start)`, неделя/статусы + тесты.
- **T3.** `service.py`: правила — создание/правка (автор или старшая; закрытая база →
  запрет), отправка, доска, закрытие/переоткрытие (предупреждение о неотправленных),
  снимки строк + тесты.
- **T4.** `report.py`: агрегация отчёта (растворы поточково + итог; остальное по группам),
  генерация .xlsx (openpyxl, 2 листа), HTML-представление + тесты на фикстуре недели.
- **T5.** Аналитика: фильтры (недели/база/точка/группа), агрегация по `sent`,
  экспорт .xlsx + тесты.
- **T6.** `router.py` + правки `domain/employee.py`, `web/app.py`, `cli.py` + API-тесты
  по ролям (doctor 403; nurse: свой/чужой/закрыто; head_nurse/head: доска, закрытие, отчёт).
- **T7.** `consult/router.py`: nurse → 403 + правка тестов консультанта; правка
  `base.html` (меню: +«Потребности», «Приказы» скрыть у nurse) + тесты меню.
- **T8.** UI: `needs.html` + `needs.js` + `needs.css`: форма сестры (точка, поиск,
  таблица количеств, сохранить/отправить), доска старшей, закрытие/переоткрытие,
  просмотр и скачивание отчёта, аналитика с фильтрами.
- **T9.** E2E без сети: сестра составила → отправила → старшая закрыла базу → отчёт
  (.xlsx с растворами поточково); после закрытия правки запрещены; doctor 403;
  nurse в чате 403; полный pytest (224 + новые); живой смоук uvicorn.
- **T10.** Документация: ADR-11 + правки ADR-5/ADR-10 в README, раздел «Потребности»,
  seed `data/needs/catalog.yaml` (64 позиции, единицы по умолчанию — заведующий поправит).

## 6. Открытые вопросы (не блокируют)

1. Единицы измерения в каталоге — дефолтные (амп/фл/туб), заведующий поправит в файле.
2. Образец формы аптеки — если появится, подгоним листы/колонки отчёта
   (сейчас: два листа).
3. Импорт формуляра аптеки (Excel) — не в v1.
4. Веб-редактирование каталога старшей — v2 (в v1 файл правит заведующий).
5. Каскадный ввод количеств (цифровая клавиатура, Enter → следующая строка) — v2.
