# Брифинг: подприложение «Потребности» (старшая сестра)

**Статус:** ВЫПОЛНЕНО. Стартовый брифинг сессии, приведший к ТЗ и реализации
`docs/ТЗ-потребности.md` (T1–T10, пакет `src/docapp/needs/`). Составлен 2026-08-10.
**Задача сессии:** собрать требования, согласовать скоуп и провести подприложение по отработанному процессу (ТЗ → план → субагенты → E2E → ревизия).

## Цель (со слов заказчика)

Дополнительное подприложение в docapp для **старшей сестры** отделения: запросы
потребностей препаратов и расходных материалов (для пополнения) + создание
отчёта по потребностям. Старшая сестра в существующем проекте (консультант
по приказам) не участвует. Структура приложения позволяет добавить
подприложение по образцу «Приказы».

## Текущее состояние проекта (для быстрого входа)

- **Стек:** Python 3.11+, FastAPI + Jinja2 + SQLite + PWA, uv, роли `doctor`/`nurse`/`head`,
  фабрика `create_app(db_path, secret)`, сессии Starlette, ADR в README, русские docstring, 224 pytest.
- **Подприложение «Приказы» (ИИ-консультант)** — реализовано по `docs/ТЗ-консультант.md`
  (задачи T1–T16): пакет `src/docapp/consult/`, полная изоляция (отдельная БД `data/consult/`,
  ленивая инициализация без сети), RouterAI, веб-загрузка с авто-переиндексацией,
  история диалогов с миграцией, чтение/скачивание приказов. **Это образец процесса и архитектуры.**
- **Эксплуатационная гигиена закрыта:** `DOCAPP_HTTPS_ONLY`, лимит аплоада 50 МБ,
  WAL + busy_timeout, бэкап-скрипт `scripts/backup.sh`, раздел деплоя в README.
- **Конвенции интеграции** (обязательны):
  - новый пакет `src/docapp/<name>/` + свой `APIRouter` + `app.state.<name>`;
  - инициализация в `create_app` — дешёвая, **без сетевых вызовов при старте** (иначе упадут web-тесты);
  - отдельная БД в `data/`, основную `docapp.db` не трогать;
  - правки существующих файлов — по явному списку (обычно: `app.py`, `pyproject.toml`, `.gitignore`, тесты заглушек);
  - тесты: pytest + TestClient (`follow_redirects=False`), tmp_path БД, фейки вместо сети, E2E-сквозной.

## Открытые вопросы (первое обсуждение)

1. **Роль:** новая роль `head_nurse` или переиспользовать `head`? Кто ещё видит/правит запросы?
2. **Модель данных:** справочник препаратов/расходки (название, единица измерения, форма выпуска)
   или свободный ввод? Учитываются ли остатки на складе или только «потребность»?
3. **Поток:** кто создаёт запросы, нужны ли статусы (черновик → подано → частично → получено),
   период потребности (месяц)?
4. **Отчёт:** формат (Excel .xlsx / PDF / веб-страница), состав (по группам, суммы, динамика)?
5. **Импорт:** нужен ли (Excel остатков, аптечная программа)?
6. **Связь с «Приказами»:** нужна ли (например, нормы расхода из приказов)? На старте, вероятно, нет — но решить явно.
