# ADR-0016. Одна база данных вместо четырёх

- **Статус:** принято
- **Дата:** 2026-09-11
- **Контекст:** ADR-6 объявил «SQLite, один файл, бэкап = копия файла». На практике
  появились ещё три БД (`data/wiki/wiki.db`, `data/needs/needs.db`,
  `data/duty/duty.db`), и ADR-6 перестал быть правдой. Дополнительно:
  `data/docapp.db` открывается тремя соединениями из трёх классов, ссылки на
  сотрудников в БД подприложений — голые `*_id` без внешнего ключа, а обход
  всех БД в `cli.py` идёт цепочкой `if name == …`.

- **Решение:** все данные приложения живут в одном файле `data/docapp.db`.
  Таблицы разделов имеют префикс владельца (`wiki_*`, `needs_*`, `duty_*`), таблицы
  ядра — без префикса (`employees`, `anesthesia`, `active_nurse`). Все ссылки на
  сотрудников — настоящие `REFERENCES employees(id)`. Версия схемы хранится не в
  `PRAGMA user_version`, а в таблице `schema_migrations` с записью на модуль.

- **Последствия:**
  - бэкап снова один файл (плюс папка PDF-источников, см. ADR-0020);
  - `docapp migrate` больше не знает имён БД поодиночке — обходит реестр модулей;
  - миграция одного модуля не может незаметно разойтись с миграцией другого;
  - изоляция модулей остаётся **логической** (владелец данных + интерфейс, ADR-0017),
    а не файловой. Сбой одного модуля теперь потенциально виден всем — это
    компенсируется транзакциями и бэкапом перед выкладкой;
  - пересматривает ADR-11 и ADR-15 в части «своя БД в `data/<имя>/`»;
    ADR-6 подтверждается в исходном виде.
