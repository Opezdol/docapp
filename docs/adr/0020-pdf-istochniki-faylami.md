# ADR-0020. PDF-источники «Компендиума» — файлами на диске

- **Статус:** принято
- **Дата:** 2026-09-11
- **Контекст:** `WikiService.add_source` кладёт PDF в БД (`source=data`, колонка
  `BLOB`), хотя `WIKI_SOURCES_DIR` в конфиге и в README обещает папку
  `data/wiki/sources`. Документация и код расходятся: заведующий думает, что файлы
  лежат на диске. При слиянии в одну БД приказ на 20 МБ попал бы внутрь
  `docapp.db` — с ростом самого файла, WAL и времени бэкапа.

- **Решение:** PDF-источник хранится файлом в папке `WIKI_SOURCES_DIR`
  (`data/wiki/sources` по умолчанию), в БД — метаданные источника и имя файла
  (`wiki_sources.stored_name`). Загрузка и удаление идут парой «файл + строка»;
  удаление источника удаляет и файл. OCR-текст и таблицы остаются в БД, как
  сейчас. Ошибка при разборе PDF (битый файл) убирает уже положенный файл, чтобы
  в хранилище не осталось мусора без записи.

- **Имя файла в хранилище — хеш содержимого** (`<sha256[:32]>.pdf`), а не
  `<id>-<имя>` из первоначальной редакции этого ADR:
  - `id` известен только после вставки строки, а имя нужно уже при записи файла;
  - хеш обезличивает имя целиком — в отделении попадаются PDF, названные по
    пациенту, а имя файла живёт в файловой системе и в бэкапах;
  - одинаковые файлы не дублируются: хеш совпал — файл уже лежит;
  - имя, под которым PDF загрузили, хранит БД (`wiki_sources.filename`) и
    показывает человеку.

- **Последствия:**
  - бэкап снова двухчастный: БД + папка источников. README это уже говорит;
    `backup.sh` правится при переносе на хостинг (тогда же из него уходят
    прежние четыре файла БД) — вместе с самим разговором о заливке;
  - отдача файла (`/sources/{id}/download`) читает диск, а не выгружает BLOB;
  - прежние источники из BLOB переносит `docapp import-legacy` (папка хранилища
    задаётся ключом `--sources-dir`): пока PDF не положен файлом, перенос
    останавливается — BLOB в старой БД единственная копия приказа;
  - отклонена альтернатива «BLOB в БД»: «один файл бэкапа» не стоит роста БД на
    десятки мегабайт и выгрузки BLOB на каждое чтение.
