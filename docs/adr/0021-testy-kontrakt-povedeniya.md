# ADR-0021. Тесты: контракт — поведение, а не внутренние интерфейсы

- **Статус:** принято
- **Дата:** 2026-09-11
- **Контекст:** 359 тестов держат функциональность, но часть из них привязана к
  внутренним интерфейсам, которые перестройка меняет: тесты хранилищ
  (`test_store.py` и родственные), фикстуры, поднимающие приложение через
  `monkeypatch` четырёх переменных окружения (`NEEDS_DB`, `WIKI_DB`, `DUTY_DB`,
  `DOCAPP_DB`), дублированные `_seed()` и `catalog.yaml` в пяти файлах. Если
  требовать «все 359 зелёными на каждом шаге», каркас придётся гнуть под тесты.

- **Решение:** контрактом считается **поведение**:
  - всегда зелёными обязаны быть сценарные и API-тесты: вход и роли, цикл заявки
    «Потребностей» (черновик → отправка → закрытие → отчёт), отчёты и доска
    «Дежурств», страницы и права «Компендиума», ввод/правка анестезий;
  - юнит-тесты хранилищ и проводки переписываются под новую архитектуру;
  - общие фикстуры и фабрики переезжают в `tests/factories.py`; приложение
    собирается с подмножеством модулей, а не со всеми четырьмя и четырьмя
    переменными окружения.

- **Последствия:**
  - на каждом шаге приёмка — «зелёный сценарный набор + новые тесты каркаса»;
  - количество тестов может временно уменьшаться — это ожидаемо и не считается
    регрессом;
  - появляются тесты, которых сегодня нет: «роль × разрешение» по таблице доступа,
    сборка приложения с подмножеством модулей, перенос данных из старых БД.
