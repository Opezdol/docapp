# ADR-0019. Каталог расходки переезжает в базу данных

- **Статус:** принято
- **Дата:** 2026-09-11
- **Контекст:** Каталог «Потребностей» (базы, точки, группы, препараты с единицами)
  хранится файлом `data/needs/catalog.yaml` с авто-перечитыванием по mtime. Решение
  «данные, не код» было принято, когда каталог правил только заведующий руками. В
  планах — **редактор расходки для старшей сестры**: правка из интерфейса, то есть
  файл перестаёт быть единственным способом изменения. Плюс `catalog.yaml` лежит в
  `.gitignore`: свежий клон или rsync без файла оставляют «Потребности» пустыми.

- **Решение:** источник правды — таблицы `needs_catalog_*` в единой БД.
  YAML остаётся для двух вещей: первичный seed (если БД пуста — залить при первом
  старте) и выгрузка («Выгрузить каталог в YAML») для резервной копии глазами.
  Каждое изменение из интерфейса пишется в журнал `needs_catalog_audit`
  (кто, когда, что добавлено/изменено/удалено); журнал видит заведующий.
  Править каталог могут старшая сестра (`head_nurse`) и заведующий (`head`).

- **Последствия:**
  - появляется история «кто убрал позицию из расходки» — раньше ответа не было;
  - строки заявок по-прежнему хранят **снимки** `item/unit/grp` (правка каталога не
    ломает историю и старые отчёты) — это решение сохраняется;
  - особую группу «Растворы» по-прежнему определяет **имя** группы: переименование
    ломает разделение на растворы/медикаменты (ADR-12);
  - `NEEDS_CATALOG` из `.env` больше не влияет на работу приложения — только на
    первичный импорт;
  - пересматривает часть ADR-11 в части «файл-каталог с авто-перечитыванием».
