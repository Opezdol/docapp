# ADR-0022. Документация: ADR — файлами, README — обзор

- **Статус:** принято, реализовано (ADR-1…15 перенесены в `docs/adr/0001…0015`, README сжат до обзора)
- **Дата:** 2026-09-11
- **Контекст:** README вырос до 601 строки и стал одновременно описанием продукта,
  инструкцией по запуску, руководством по деплою на reg.ru, справочником переменных
  окружения и архивом архитектурных решений (ADR-1 … ADR-15 внутри текста). Номера
  ADR цитируются в ТЗ и в комментариях кода, поэтому переиспользовать их нельзя.

- **Решение:**
  - каждое решение — отдельный файл `docs/adr/NNNN-короткое-имя.md` в формате
    «Статус / Дата / Контекст / Решение / Последствия»;
  - существующие ADR-1 … ADR-15 переносятся в файлы **с сохранением номеров**;
  - новая нумерация продолжается с 16; уже написанное ТЗ «Отчёт» (начисления)
    планировало номер 16 — оно получает 0024, ссылка в `docs/ТЗ-отчёт.md` исправлена;
  - README после ревизии читается как «что это, как запустить, из чего состоит» и
    **ссылается** на ADR, а не содержит их;
  - терминология — по `docs/глоссарий.md`; слово «подприложение» из документов
    и комментариев удаляется.

- **Последствия:**
  - ссылки «см. ADR-11» в коде и ТЗ остаются валидными (номера не меняются);
  - ADR перестают конфликтовать в одном файле и видны в истории git по одному;
  - ревизия README выполняется отдельным шагом после перестройки кода, чтобы
    описывать то, что уже есть, а не то, что планируется.
