# ADR-0023. Роли и доступ: одна таблица разрешений

- **Статус:** принято
- **Дата:** 2026-09-11
- **Контекст:** Права были размазаны по четырём этажам: условия jinja в
  `web/templates/base.html`, три разных набора `_require_*` в роутерах, константы
  `ALLOWED_FULL`/`CURATOR_ROLES` в сервисах и проверка роли в `web/app.py`. Смена
  доступа означала grep по шести файлам, а теста «роль × раздел» не существовало.
  Дополнительно обнаружились два расхождения кода с документацией: `editor` попадал
  в ветку врача и мог вводить анестезии, а ADR-5 обещал, что заведующий видит все
  записи, тогда как код отдаёт ему только свои.

- **Решение:**
  1. Разрешения задаются **одной таблицей** `ALLOWED` в `core/access.py`
     (`роль → набор разрешений вида «модуль.действие»`). Таблица — единственный
     источник правды; меню строится из неё же.
  2. **`editor` — это врач** с дополнительным правом курирования справочных
     документов: права врача (свои анестезии — просмотр и ввод; свой отчёт
     дежурства; свой итог начислений) плюс `wiki.read`, `wiki.curate`.
  3. **ADR-5 в части «заведующий видит всех» отменяется.** Заведующий видит только
     свои анестезии — это фактическое поведение системы, подтверждено владельцем
     11.09.2026. Полный обзор записей появится в модуле «Отчёт» (начисления,
     `docs/ТЗ-отчёт.md`) — отдельным ТЗ.
  4. Остальные нормы ADR-5 (врач видит и правит только свои записи; медсестра —
     только просмотр своих; пароли — только хеш) сохраняются.

- **Последствия:**
  - пересматривает ADR-5 (частично) и ADR-9 в части проверок ролей;
  - у редактора появляется доступ к «Дежурствам» — он врач. Если редактор у нас
    в ночные смены не ходит, право снимается одной строкой таблицы;
  - `_require_*` в роутерах исчезают, остаётся `require(request, "<модуль>.<действие>")`;
  - появляется тест, который проверяет таблицу целиком, без HTTP.
